
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：品牌 / 型号 / 产品名 / 公司名 / 渠道或机构名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是型号 / 代号 / 没信息量的 teaser（如 "BE85"、"Meet the new standard"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "Firmware 1.2.4" + 来源 "TP-Link Deco：固件更新" → "TP-Link Deco 固件 1.2.4 更新"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体型号时，用上位词（如"Wi-Fi 7 Mesh 系统"）兜底，绝不凭"行业常识"编一个具体型号 / 版本 / 数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Benchmark 这类解释、分析、教程或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的产品、规则或新数据，就改写成“发布 / 推出 / 上线 / 开源”。只有原标题明确宣布了发布、推出、上线或开源，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的公司、产品、项目名。
   例：原标题 "How Wi-Fi 7 MLO keeps your Deco mesh stable" → "Wi-Fi 7 MLO 如何让 Deco Mesh 更稳定"，不能写成 "TP-Link 发布 Wi-Fi 7 MLO"。
   例：原标题 "How to set up a deal for Black Friday" + 来源和正文明确是 Amazon Seller Central → "Amazon Seller Central 如何设置黑五促销"，不能只写成缺主体的 "如何设置黑五促销"。
6. 本条的动作和背景里的旧发布要分清：原文把发布写成过去的事（“At DevDay, we introduced …”“Last week we launched …”“上周我们发布了…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把发布交代成此前的事；不能写成“推出 / 发布 / 上线”，否则读者会当成今天的新闻。只有原文明确某项能力是现在才开放或新增，才对那一项用对应动作。
   例：正文 "At CES, we introduced the Archer BE900 … See how it works below" → "TP-Link 演示 CES 发布的 Archer BE900 用法"，不能写成 "TP-Link 在 CES 推出 Archer BE900"。
